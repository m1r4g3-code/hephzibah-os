# Hephzibah Design System — Terminal Precision

The visual operating system. Every artifact Emmanuel produces — LinkedIn cards, Upwork portfolio slides, proposal PDFs, product mockups, case studies — is generated by this system. Every renderer imports from here. No exceptions.

This is not a style guide. It is a design intelligence encoded from the world's best designers, translated into rules a script can execute.

---

## The Masters — Who We Stole From

### Josef Müller-Brockmann (Grid Systems in Graphic Design)
The grid is the architecture beneath every layout. Not aesthetic — structural. Every element on a surface occupies a grid column, not a random position.
> "The formal organisation of the surface by means of the grid, a knowledge of the rules that govern legibility, and the meaningful use of colour are among the tools a designer must master."

### Massimo Vignelli (The Vignelli Canon)
Structure before style. Hierarchy before aesthetics. Typography is information organization, not self-expression. White space is not emptiness — it is the rhythm that makes the content breathe.
> "The most important device was the management of white space in layouts — the white space makes the layout sing."

### Dieter Rams (Ten Principles of Good Design)
As little design as possible. Every element earns its place. Honest. Timeless. Thorough to the last detail.
> "Less is more only when more is too much."

### Robert Bringhurst (Elements of Typographic Style)
Typography is not decoration. It is the vessel for information. Line length, leading, tracking, alignment — each has a correct value derived from legibility science, not preference.

### Linear (Dark-First Digital Design)
Darkness as a native medium, not an inversion. Near-black canvas. Subtle opacity gradations. One electric accent used sparingly. Information density managed through type weight, not color.

### Stripe (Editorial + Data-Forward)
Every gap is a deliberate typographic choice. Numbers and data get tight density. Chrome around them gets generous whitespace. The contrast between dense data and open space creates hierarchy without decoration.

### PORTO ROCHA (Systems Thinking)
Identity as a living system that flexes across contexts, not a static logo. Intentional originality. "Originality has a lot to do with being intentional."

### Gestalt Psychology
The eye perceives wholes before parts. Proximity determines grouping. Similarity implies same function. Figure-ground contrast determines what is signal and what is background. Every layout decision is a perception decision.

## The Philosophy — What This System Believes

**1. Signal over decoration.**
Every element that does not carry information is removed. Borders, gradients, shadows — only if they serve legibility or hierarchy. Nothing is decorative.

**2. Numbers are the hero.**
Production metrics, proof points, statistics — these are displayed large and first. The number IS the design. "48 RELEASES" in 89px Poppins 800 says more than any paragraph.

**3. The grid is non-negotiable.**
Every element snaps to an 8pt grid. No exceptions. Spacing between elements is never invented — it is selected from the spacing scale. The grid is what separates professional from amateur work.

**4. Typography carries the page.**
Before any color lands, the type hierarchy must communicate the structure. Display → Heading → Body → Label → Caption. The weight contrast and size contrast do the work.

**5. One accent. One surface.**
Lemon (#E8FF3A) appears once per content surface. When it appears, it means something. It is never used for decoration. It marks the most important element: the number, the CTA, the result.

**6. Dark is the native medium.**
This system is dark-first. Not because it looks cool — because technical systems run in the dark. Code runs in terminals. n8n runs at 3AM. The canvas is #080808 and content is revealed from it, not placed on it.

**7. Whitespace is breathing room.**
Cramming is amateur. Professional design uses space generously. The ratio of white space to content tells the viewer: this work has confidence. It does not need to fill every pixel.

**8. Every output is a story with a resolution.**
No output is just "a graphic." Every piece has a structure: situation → mechanism → proof → result. The design reveals the story, it does not decorate it.

## Typography System

### Typefaces

```
DISPLAY      Poppins 700 / 800
             Used for: big numbers, hero headlines, stat blocks
             Never used for: body copy, long text

BODY         Inter 300 / 400 / 500
             Used for: all reading text, proposals, captions
             The workhorse. Invisible but essential.

MONO         JetBrains Mono 400 / 500
             Used for: labels (UPPERCASE), metadata, tags, code, technical specs
             The signal that something is data, not prose.
```

### Type Scale (Perfect Fourth ratio — 1.333)
*Base: 16px. Scale generated mathematically. Every size is intentional.*

```
LABEL      11px  / 0.688rem   — UPPERCASE, +0.10em tracking, Mono
CAPTION    12px  / 0.75rem    — tertiary information
SMALL      14px  / 0.875rem   — supporting text
BASE       16px  / 1rem       — body copy (the reference point)
MD         21px  / 1.313rem   — lead paragraphs, sub-headings
LG         28px  / 1.75rem    — section headings
XL         37px  / 2.313rem   — page titles
2XL        50px  / 3.125rem   — major display
3XL        67px  / 4.188rem   — hero display
DISPLAY    89px  / 5.563rem   — STAT NUMBERS (the hero element)
```

### Line Height Rules (Bringhurst)
```
Display text (3XL+):     1.0  — tight. numbers need no breathing room.
Heading (XL–2XL):        1.15 — slightly open for readability at size
Subheading (LG–XL):      1.25
Body (BASE–MD):           1.6  — generous. reading text needs room.
Caption / Label:          1.4
```

### Tracking Rules (Bringhurst)
```
Display numbers:   -0.03em  — slightly tighter at large sizes
Headings (LG+):   -0.02em  — tighten headings slightly
Body (BASE):       0em      — neutral, never touch body tracking
Labels (MONO):    +0.10em   — uppercase labels must be letter-spaced
NEVER letter-space lowercase body text. This is Bringhurst's law.
```

### Line Length (Bringhurst)
```
Optimal:           66 characters per line
Acceptable range:  45–75 characters
Short text (<45):  Flush left, ragged right (never justified)
Never:             Full justification (creates rivers)
```

## Spacing System (8pt Grid — Müller-Brockmann + Material Design)

*Every spacing value is a multiple of 8. No invented values.*

```
SCALE
  2:    2px   — hairline gap (rarely used)
  4:    4px   — tight (inline elements, icon gaps)
  8:    8px   — xs (compact padding, tight rows)
  12:   12px  — sm (tag padding, dense UI)
  16:   16px  — md (standard component padding)
  24:   24px  — lg (section-internal spacing)
  32:   32px  — xl (between major components)
  40:   40px  — 2xl (section padding)
  48:   48px  — 3xl (generous section padding)
  64:   64px  — 4xl (section separation)
  80:   80px  — 5xl (hero section padding)
  96:   96px  — 6xl (page-level separation)
  128:  128px — section (between major page blocks)
```

### Internal ≤ External Rule (Gestalt Proximity)
*Padding inside a component must never exceed the margin between components.*
```
Card internal padding:   24px
Gap between cards:       32px (must be ≥ 24px — external ≥ internal)

Button internal padding: 16px vertical, 24px horizontal
Gap between buttons:     8px

Section padding:         48px top/bottom
Section gap:             64px
```

### Standard Component Heights (8pt)
```
Button standard:    40px (5×8)
Button small:       32px (4×8)
Input field:        40px (5×8)
Icon small:         16px (2×8)
Icon standard:      24px (3×8)
Icon large:         32px (4×8)
Avatar small:       32px (4×8)
Avatar standard:    40px (5×8)
Avatar large:       64px (8×8)
Tag/pill:           24px (3×8) height
```

## Grid Layout System (Müller-Brockmann)

### Columns
```
Mobile (≤640px):      4 columns,  16px margins, 16px gutters
Tablet (641–1024px):  8 columns,  32px margins, 24px gutters
Desktop (1025–1440px): 12 columns, 48px margins, 24px gutters
Wide (1441px+):       12 columns, auto margins, 32px gutters (max content: 1280px)
```

### The "www" rule (Vignelli whitespace)
Left and right margins must breathe. Content never touches the edge of a surface.
Minimum margin on any side: 16px. Preferred: 24px+. Generous: 48px+.

## The Stat Block — The Signature Element

Every Hephzibah output that contains proof MUST use this element correctly.

The stat block is the single most important design element in the system. James D. understood this instinctively. Every number that proves a claim gets displayed at DISPLAY size (89px) or 3XL (67px) minimum.

### Anatomy of a Stat Block
```
[DISPLAY SIZE NUMBER]   ← Poppins 800, color: accent OR text-primary
[LABEL]                 ← JetBrains Mono UPPERCASE 11px, text-tertiary, +0.10em tracking
```

### Rules
1. Numbers in stat blocks: Poppins 800, at minimum 3XL (67px)
2. The most important stat gets the accent color (#E8FF3A)
3. All other stats in that block: text-primary (#F4F4F4)
4. Labels always: JetBrains Mono UPPERCASE, text-tertiary
5. Stat blocks use tabular numerals: `font-variant-numeric: tabular-nums`
6. Never mix 3+ semantic colors in a single stat block
7. Maximum 4 stats per block (Gestalt: chunking limit is 4)

### SERAMAN Stat Block Example
```
4              WORKFLOWS
↓ accent

7              VIDEOS / WEEK
↓ text-primary

0              MANUAL STEPS
↓ success (#00E066)

5★             CLIENT RATING
↓ text-primary
```

## Design Rules — Non-Negotiable (Rams + Vignelli + Müller-Brockmann)

1. **Every spacing value comes from the 8pt scale.** No 17px margins. No 13px padding. If it doesn't snap to the scale, it is wrong.

2. **Every element aligns to the column grid.** Nothing floats. Text starts on a column. Images span columns. Stat blocks span columns.

3. **Hierarchy is communicated by size and weight contrast, not color.** Color confirms hierarchy — it does not create it. If the hierarchy disappears when you remove color, the layout is broken.

4. **One accent per surface.** The lemon accent (#E8FF3A) appears once. If it appears twice, it means nothing both times.

5. **Labels are ALWAYS uppercase, monospace, widely tracked.** No exceptions. If text is metadata, it is treated as a label: JetBrains Mono, UPPERCASE, +0.10em tracking.

6. **Body text is always flush left, ragged right.** Never justified. (Bringhurst)

7. **Line lengths stay between 45–75 characters for body text.** (Bringhurst)

8. **Internal padding ≤ external margin.** (Gestalt proximity — grouping law)

9. **White space is not empty.** It is the rhythm. Every margin is chosen. Nothing collapses accidentally.

10. **As little as possible.** (Rams) Before adding any element, ask: does removing this break the communication? If no, remove it.

11. **Numbers display large.** Production metrics, proof stats, client outcomes — these get DISPLAY or 3XL treatment. They are the content. They are not supporting evidence.

12. **Every output is a complete story.** Every artifact has a beginning (situation/context), middle (mechanism/how), and end (result/proof). The design reveals this structure.

## The Renderers — What Gets Built

Each renderer is a Python script that accepts JSON data + format flag → outputs designed file.

```
SCRIPTS (to build in order)

design_tokens.py          ← NOT a renderer. The shared token file.
                             All other renderers import from here.
                             Contains: colors, typography, spacing, shadows as Python dicts.

portfolio_renderer.py     ← Upwork portfolio piece: 4-slide set
                             Input: project data JSON
                             Output: 4 PNG files (hero + canvas + proof + result)
                             Formats: portfolio-hero, portfolio-slide

card_renderer.py          ← LinkedIn cards (upgrade of render_card.py)
                             Input: post content + type
                             Output: PNG (square or landscape)
                             Formats: linkedin-square, linkedin-landscape

case_study_renderer.py    ← Case study document
                             Input: client + problem + solution + result + metrics
                             Output: PDF (4–6 pages)
                             Formats: a4, letter

mockup_renderer.py        ← Product/app showcase
                             Input: screenshot path + context
                             Output: PNG in browser/phone/dashboard frame
                             Formats: browser-frame, phone-frame, dashboard-frame

carousel_renderer.py      ← LinkedIn carousel (multi-slide story)
                             Input: slide data array
                             Output: multiple PNGs (1080×1080 per slide)
                             Formats: linkedin-square

proposal_renderer.py      ← Already exists. Governs: proposal PDF output.
                             Upgrade to use design_tokens.py for consistency.
```

## Quality Gate — How to Know If Output Is Good Enough

Before any rendered file is used, run this check:

```
□ Does every spacing value come from the 8pt scale?
□ Does every element align to the grid?
□ Is the accent color (#E8FF3A) used exactly once?
□ Is the hierarchy clear WITHOUT color? (Remove color mentally — is structure still clear?)
□ Are all labels in JetBrains Mono UPPERCASE?
□ Is the key metric displayed at DISPLAY or 3XL size minimum?
□ Is there sufficient whitespace? (If it feels cramped, it is cramped)
□ Does every element earn its place? (Would removing it break the communication?)
□ Is this output a complete story (situation → mechanism → result)?
□ Would a senior designer at Pentagram, Porto Rocha, or Linear approve this?
```

If any box is unchecked, revise before shipping.
